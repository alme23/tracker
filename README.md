# Tracker: Система Автономного Крипто-Аудита Рабочих Станций Windows

**Tracker** — это легковесный, безопасный и полностью автономный программный комплекс класса ITAM (IT Asset Management), предназначенный для автоматического сбора, шифрования и централизованного учета аппаратных и системных характеристик рабочих станций под управлением ОС Windows.

Проект разработан на языке **Go** с соблюдением принципов чистой архитектуры. Комплекс полностью независим от внешних тяжелых библиотек, не использует CGO (компилируется без GCC) и не требует развертывания инфраструктуры сертификатов (CA).

---

## 🏗 Архитектурные Особенности и Стек

### 1. Фоновый Агент (`cmd/agent`)
* **Низкоуровневый сбор:** Пакет `pkg/collector` осуществляет сбор метрик напрямую через Win32 API системные вызовы (`syscall`, `unsafe`) и парсинг реестра Windows. Полностью изолирован от медленного WMI и команд PowerShell.
* **Скрытность (Stealth):** Компилируется с флагом `-H=windowsgui`, что позволяет ему выполняться в фоновом режиме без всплывающих черных окон консоли `cmd.exe`.
* **Легковесность:** Не требует прав Администратора для 95% метрик, запускается мгновенно как одноразовая задача.

### 2. Центральный Приемник (`cmd/server`)
* **Кроссплатформенность:** Благодаря использованию драйвера **`modernc.org/sqlite` (Pure Go)**, сервер скомпилирован со значением `CGO_ENABLED=0` и может беспрепятственно разворачиваться на Linux, Windows или внутри Docker-контейнеров.
* **Умная Delta-фильтрация (Time-Series):** Сервер автоматически сопоставляет входящие пакеты с историей в БД по Machine GUID. Новая реляционная строка создается **только при физическом изменении железа** (смена процессора, видеокарты, подмена/кража диска). Если конфигурация идентична — атомарно обновляется лишь `timestamp` онлайна, экономя гигабайты места на SSD.
* **Graceful Shutdown:** Корректно перехватывает сигналы `SIGINT` / `SIGTERM` (`Ctrl+C`), завершает активные транзакции горутин и безопасно закрывает пул SQLite без риска повреждения файлов.
* **Конфигурация:** Настраивается без перекомпиляции через легковесный локальный файл `.env`.

### 3. Криптографический Слой и Сеть (`internal/crypto`)
* **Автономия от SSL/TLS:** Проект не использует постоянные сертификаты безопасности. Защита трафика построена на базе **ECDH (Elliptic Curve Diffie-Hellman на кривой P-256)**.
* **Сессионные ключи:** Для каждого подключения агент и сервер обмениваются открытыми ключами «на лету», вычисляют общий секрет, хешируют его через **SHA-256** и шифруют трафик по стандарту **AES-256-GCM** (свойство *Perfect Forward Secrecy*).
* **Сжатие:** Бинарный поток данных **GOB** сжимается архиватором **Gzip** перед шифрованием, снижая сетевую нагрузку до пары килобайт на хост.

### 4. Автообнаружение через DNS SRV (`internal/dns`)
* Агент полностью избавлен от захардкоженных IP-адресов. Он считывает имя текущего Active Directory домена и запрашивает промышленную SRV-запись `_tracker._tcp.[домен]`, автоматически узнавая актуальный хост и порт сервера.

## 🛠 Настройка Инфраструктуры

### 1. Настройка DNS SRV (Контроллер Домена Windows Server)
Для автоматического обнаружения сервера агентами, добавьте в DNS-зону вашего домена (например, `domain.tld`) новую запись:
* **Служба (Service):** `_tracker`
* **Протокол (Protocol):** `_tcp`
* **Приоритет / Вес:** `0` / `0`
* **Номер порта:** `9000` *(или порт из вашего файла .env)*
* **Узел (Target host):** `tracker.domain.tld` *(или прямой IP-адрес сервера приемника)*

### 2. Конфигурация Сервера (`.env`)
Создайте файл `.env` в папке рядом с исполняемым файлом сервера:
```env
SERVER_HOST=0.0.0.0
SERVER_PORT=9000
SHOW_DEBUG_LOGS=true
DB_FILE=tracker.db
```

## 🚀 Сборка проекта

### Компиляция Сервера (под Linux/Windows)
```bash
go mod tidy
go build -o bin/server cmd/server/main.go
```

### Компиляция Агента (строго под Windows, скрытый режим)
Вы можете скомпилировать Windows-агента на любой ОС (включая Linux) благодаря кросс-компиляции Go:
```bash
GOOS=windows GOARCH=amd64 go build -ldflags="-H=windowsgui -s -w" -o bin/agent.exe cmd/agent/main.go
```
*Флаги `-s -w` очищают бинарник от отладочной информации DWARF, уменьшая его вес и усложняя декомпиляцию.*

## 📊 Реляционная Структура Базы Данных (SQLite)

Система автоматически разворачивает 4 реляционные таблицы со связью `One-to-Many` и каскадным удалением логических зависимостей (`ON DELETE CASCADE`):

1. **`host_metrics`**: Главные паспортные данные ПК (Имя, FQDN, ОС, Сборка, Пользователь, Модель ЦП, Общая RAM, IP-клиента).
2. **`gpu_metrics`**: Массив установленных видеокарт (Name, VendorID, DeviceID, Объем памяти).
3. **`disk_metrics`**: Массив локальных физических накопителей (Буква, Тип шины, Модель, Серийный номер, Общий объем).
4. **`network_metrics`**: Массив всех сетевых адаптеров системы (Имя, MAC, Статус Up/Down, Тип DHCP/Static, Список IP-адресов строкой).

## 🪟 Инструкция по Развертыванию Агента в Организации

Так как `agent.exe` является одноразовой легковесной консольной утилитой без окон, его запуск на рабочих станциях рекомендуется автоматизировать через **Групповые политики Active Directory (GPO)**:

1. Положите файл `agent.exe` в сетевую папку контроллера домена, доступную для всех ПК (например, `\\domain.local\NETLOGON\tracker\`).
2. Откройте `Управление групповыми политиками` (`gpmc.msc`).
3. Создайте новую политику и перейдите в: **Конфигурация компьютера -> Настройки -> Параметры панели управления -> Планировщик задач** (Task Scheduler).
4. Создайте *Немедленную задачу* (Immediate Task) или задачу по расписанию:
   * **Действие:** Запуск программы
   * **Программа/сценарий:** `\\domain.local\NETLOGON\tracker\agent.exe`
   * **Пользователь:** `NT AUTHORITY\SYSTEM` (или `Пользователь, вошедший в систему` — для точного определения DisplayName сотрудника).
5. Примените политику к целевым организационным юнитам (OU) с компьютерами. При каждом включении или раз в сутки агент будет бесшумно отправлять актуальный срез данных на ваш сервер.
